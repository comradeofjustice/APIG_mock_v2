# Env Assistant Terminal Setup Skill

将 `env-assistant` 的 CLI 向导经验复用为稳定流程，帮助用户在终端完成前端项目启动准备。

## 交互模式（默认直接执行）

默认采用“触发即执行”模式，不走聊天问答流程：

1. 触发该 skill 后，优先在终端直接执行内置脚本：`node scripts/index.mjs`。
2. 让用户在终端里按脚本提示逐步选择（仓库、目录、分支、是否安装依赖、是否启动）。
3. 仅在以下情况改用对话提问：
   - 用户明确说“不想在终端里交互”
   - 终端执行失败且需要补充参数排障
4. 不要一次性在聊天里收集全部参数；以终端交互为主。

## 适用场景

- 需要从仓库快速拉起一个前端项目。
- 用户不熟悉 Git / Node / 包管理器，希望有步骤化指引。
- 需要标准化执行：克隆、分支处理、依赖安装、本地启动。
- 出现权限、网络、包安装失败等常见问题，需要友好排查建议。

## 输入信息（终端脚本收集）

默认由终端脚本自动收集以下信息：

1. 仓库地址（模板仓库或自定义仓库）。
2. 本地目标根目录与项目目录名。
3. 分支策略：
   - 直接使用已有分支
   - 基于某分支创建新分支并推送
4. 是否自动安装依赖。
5. 是否自动启动项目。

若脚本正常运行，不需要在对话里提前收集。

### 对话回退时的提问顺序（仅故障场景）

1. 选择项目来源：模板仓库 / 自定义仓库
2. 若自定义：输入仓库地址
3. 输入本地根目录（默认 `~/workspace`）
4. 输入项目目录名（默认值可回车）
5. 选择分支模式：使用已有分支 / 基于基础分支新建
6. 若使用已有分支：选择或输入目标分支
7. 若创建新分支：选择或输入基础分支，再输入新分支名
8. 是否自动安装依赖
9. 是否自动启动项目
10. 最后进行一次“配置确认”再执行

## 标准执行流程

按如下顺序执行，避免遗漏：

1. 检查 `node` 和 `git` 是否可用。
2. 准备目标目录，若冲突则：
   - 重新命名，或
   - 自动追加数字（`-1`, `-2`...）。
3. 若目录已有同仓库代码，可询问是否复用并跳过重新克隆。
4. 克隆代码（或复用现有目录）。
5. 获取远程分支列表（`git ls-remote --heads origin`）。
6. 按分支策略执行：
   - 使用已有分支：`git checkout <branch>`
   - 基于分支建新分支：`checkout base -> checkout -b -> push -u origin`
7. 检查 `package.json` 是否存在：
   - 不存在：跳过安装/启动并解释原因
8. 自动识别包管理器：
   - `packageManager` 字段优先
   - 锁文件推断其次（pnpm/yarn/npm）
   - 默认 npm
9. 安装依赖：
   - 首次失败时，删除 `node_modules` 与 lock 文件后重试一次
10. 启动项目：
   - 优先 `dev`，其次 `start`
   - 给出本地访问地址提示（通常 `localhost:5173` 或配置端口）

## 关键决策规则

- **包管理器可用性**：若 `pnpm`/`yarn` 缺失，优先尝试 `npx <pm>`，再降级到 `npm`。
- **Node 版本提醒**：若项目声明 `engines.node` 与当前主版本不一致，先提示风险并征询继续。
- **目录安全**：默认不覆盖已有目录内容；冲突时必须用户确认策略。

## 常见错误处理文案

- **认证失败（401/403）**：提示检查仓库权限、账号或 Token 配置。
- **网络失败（DNS/内网不可达）**：提示检查 VPN/内网与仓库地址可访问性。
- **Git 未安装**：提示安装 Git 并确保在 PATH 中可用。
- **无启动脚本**：明确说明 `package.json` 中缺失 `dev/start`，需手动补充。

## 输出格式

默认按以下结构回复，保持用户可读性：

1. 当前步骤（例如：环境检测/拉代码/分支处理/安装依赖/启动）。
2. 执行结果（成功/失败 + 关键信息）。
3. 下一步动作（继续执行或给出修复建议）。

在“收集参数阶段”，每轮输出改为：

1. 当前步骤（如：`步骤 3/10：选择本地目录`）
2. 已确认信息（仅列已确定项）
3. 当前问题（单选/输入）

## 分发版内置脚本（优先）

对外分发时，优先使用本 skill 自带脚本，保证可移植性：

- 脚本：`scripts/index.mjs`
- 依赖声明：`scripts/package.json`
- 首次使用安装依赖：在 `scripts/` 目录执行 `npm install`
- 运行：`node scripts/index.mjs`

## 兼容性要求

- Node.js（建议 LTS）
- Git（需在 PATH 可用）
- npm（用于安装 `prompts` 依赖）
- 网络可访问目标仓库（内网仓库需 VPN/内网）

## 与源仓库代码对齐点

该 skill 的流程与以下实现保持一致：

- `scripts/index.mjs`（本 skill 内置分发副本，分发时以此为准）
- `env-assistant/cli/index.mjs`
- `env-assistant/scripts/frontend-setup.command`（或打包产物中的同名脚本）
- `env-assistant/scripts/frontend-setup.bat`（或打包产物中的同名脚本）

若上游 `env-assistant/cli/index.mjs` 更新，需同步更新 `scripts/index.mjs`，避免行为漂移。
