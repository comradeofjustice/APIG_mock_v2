# Code → PRD 回写

将代码与需求文档双向同步。支持三种模式：增量回写已有 PRD，或从零从代码逆向生成全新 PRD。

---

## 使用时机

- Stage 4 代码完成后，发现实现细节与 PRD 描述不符（增量回写）
- 代码阶段新增了 PRD 未描述的交互逻辑或状态（增量回写）
- 有代码但完全没有 PRD，需要从零建立需求文档（从零生成）
- 用户说"代码改了，同步到文档"、"从代码生成 PRD"、"逆向生成文档"等

---

## 【模式检测（执行前必须判断，优先执行）】

```
全流程模式判定（以下条件全部满足）：
  □ docs/ux/{模块名}/session-state.md 存在
  □ session-state.md 中包含 Stage 4 相关记录
  □ docs/ux/{模块名}/prd.md 存在

→ 全流程模式：直接进入「执行前提检查」，路径已知，跳过 Step 0
→ 独立使用模式（session-state 缺失，但 PRD 文件存在）：进入 Step 0 收集必要信息
→ 从零生成模式（PRD 文件不存在，或用户明确说"从零"/"没有 PRD"）：
    进入 Step 0，用户选择「从零生成」后跳转至 Step G0
```

> **从零生成模式判定信号**（以下任一条件触发）：
> - 用户说"没有 PRD"、"从零生成文档"、"逆向生成"、"代码没有需求文档"
> - Step 0 执行后，用户指定的 PRD 路径文件不存在
> - 全流程模式检测时 prd.md 不存在（降级为从零生成而非报错）

---

## Step 0：路径自定义（独立使用模式 / 从零生成模式执行）

```
AskQuestion(
  prompt: "请指定本次操作的来源和目标：",
  options: [
    { id: "auto",       label: "自动推断——提供模块名，使用全流程标准路径（docs/ux/{模块名}/prd.md）" },
    { id: "manual",     label: "手动指定——我来提供代码文件路径和 PRD 文件路径（PRD 已存在，增量更新）" },
    { id: "create_new", label: "从零生成——目标 PRD 不存在，从代码逆向扫描生成完整需求文档" }
  ]
)
```

- 选"自动" → 收集模块名，按 `docs/ux/{模块名}/prd.md` 路径推断；若文件不存在自动转为「从零生成」
- 选"手动" → 依次收集：
  1. 代码文件路径（可多个，支持粘贴路径或 @引用）
  2. PRD 文件路径；若文件不存在自动转为「从零生成」
  3. 版本快照存放位置（见下方「快照路径询问」）
- 选"**从零生成**" → **跳转至 Step G0**，不进入执行前提检查

**快照路径询问**（手动模式且目标目录无 versions/ 时）：
```
AskQuestion(
  prompt: "版本快照存放位置：",
  options: [
    { id: "sibling",  label: "与 PRD 同目录下的 versions/ 子目录（自动创建）" },
    { id: "custom",   label: "自定义路径（我来指定）" },
    { id: "skip",     label: "跳过快照，不保存历史版本" }
  ]
)
```

## 【从零生成流程 Step G0-G3】（仅从零生成模式执行，完成后直接到输出摘要，不进入下方执行前提检查）

```
Step G0：确认扫描范围 + 输出格式

  格式选择：
  AskQuestion(
    prompt: "从零生成 PRD 的格式：",
    options: [
      { id: "standard",    label: "标准格式（§4.2 页面清单 + §4.3 功能描述 + §6.x 状态机 + 验收用例）" },
      { id: "lightweight", label: "轻量格式（只有页面清单 + 功能描述，不含状态机和验收用例）" }
    ]
  )

  扫描范围确认：
    Glob src/views/**/*.vue → 列出所有页面级组件（排除 components/ 子目录内的非页面组件）
    Glob src/router/**/*.{ts,js} → 提取路由结构
    展示检测到的页面列表
    AskQuestion(
      prompt: "以下页面将被扫描并纳入 PRD，请勾选本次需要生成文档的范围（默认全选）：",
      allow_multiple: true,
      options: [每个检测到的页面文件一个 option，含路由路径和文件名]
    )

  输出路径确认：
    若用户已在 Step 0 提供路径 → 使用该路径
    否 → 询问：新 PRD 文件保存路径（默认：docs/ux/{模块名}/prd.md）

Step G1：代码考古扫描（对每个选定页面依次执行）

  Read 路由文件 → 提取：路由路径、页面名称、meta 信息（权限/角色/是否公开）
  Read 页面组件文件 → 系统提取以下信息：

    页面基本信息：
      - 页面标题 / 用途（从文件注释 / 组件名 / 页面标题文字推断）
      - 路由路径和参数

    交互和操作：
      - 主要按钮和操作（从 @click 处理函数名 / 按钮文字推断）
      - 表单字段（从 el-form-item / a-form-item 的 label 和 prop 提取）
      - 筛选条件（从搜索区的 v-model 字段提取）

    数据模型：
      - 字段定义（从 interface / type / defineProps / ref<T> 变量推断字段名、类型、枚举值）
      - 列表字段（从 el-table-column / a-table columns 的 prop 提取）

    状态流转（标准格式时）：
      - 状态枚举（从 status/state 变量的枚举或常量提取）
      - 状态流转（从条件渲染 / 操作按钮的显示条件推断流转关系）

    接口依赖：
      - API 调用（从 fetch/axios/useXxx composable 推断接口路径和用途）

    异常边界：
      - 错误处理（从 try/catch / .catch() / error state 的 v-if 推断）
      - 空状态（从 v-if="!list.length" / Empty 组件推断）

    权限：
      - 角色权限（从路由 meta.roles / v-permission 指令 / v-if="hasPermission()" 推断）

Step G2：生成前确认大纲（必须执行，不得跳过）

  展示扫描结果摘要：
    - 页面清单（N 个页面，每个页面的路由路径和用途）
    - 每个页面的核心功能点（3-5 条）
    - 检测到的数据字段数量
    - 发现的 API 接口数量
    - 状态机条目数量（标准格式）

  AskQuestion(
    prompt: "以下内容将写入 PRD，请确认（可取消不需要的页面）：",
    allow_multiple: true,
    options: [
      每个页面一个 option（含页面名 + 功能点数量摘要）,
      { id: "supplement", label: "有遗漏内容，我要补充（确认后告知补充内容）" }
    ]
  )
  - 用户取消勾选的页面 → 从生成范围中移除
  - 用户选择「有遗漏，我要补充」→ 等待用户描述后追加到生成内容

Step G3：生成并写入新 PRD

  按用户选择的格式生成完整 PRD，Write 到指定路径：

  文件开头必须包含免责声明：
  > ⚠️ 本 PRD 由代码逆向生成（{日期}）。AI 依据代码结构推断产品意图，
  > 可能存在理解偏差。建议人工核对：业务规则描述、状态机流转条件、验收用例的业务逻辑。

  标准格式生成内容：
    §1 背景与目标（从页面用途和功能点推断）
    §4.2 页面清单（从路由和页面组件直接提取）
    §4.3 功能描述（从交互和操作推断）
    §5 数据模型（从字段定义提取）
    §6.x 状态机（从状态枚举和流转条件生成）
    §7 接口依赖（从 API 调用列表生成）
    §9.x 异常边界（从 error state 和空状态推断）
    §11 权限矩阵（从 meta.roles 和 v-permission 推断）
    §12 验收用例（按主流程和异常路径生成测试场景骨架）
    ## 变更记录
      | {日期} | 从代码逆向生成（初始版本）|

  轻量格式生成内容：
    §1 背景与目标
    §4.2 页面清单
    §4.3 功能描述
    §5 数据模型（简化）
    ## 变更记录
      | {日期} | 从代码逆向生成（初始版本）|

  执行版本快照：
    Shell mkdir -p {PRD所在目录}/versions/
    Shell cp {PRD路径} {PRD所在目录}/versions/s0-prd-from-code-{YYYYMMDD}.md
    （快照命名用 s0 表示从零生成，区别于 s4 回写快照）
```

## 执行前提检查

```
1. PRD 文件是否存在？
   全流程模式：docs/ux/{模块名}/prd.md
   独立使用模式：用户在 Step 0 指定的路径
   否 → 停止，提示用户提供正确路径

2. 变更来源是否明确？（至少满足一项）
   - 用户描述了改动内容
   - 用户指定了改动文件路径（可 Read）
   - 当前对话中有代码变更上下文
   全部缺失 → 调用 AskQuestion（见「变更来源空白处理」）

3. 全流程模式：读取 session-state.md「已知问题」节，了解推迟到 Stage 4 的问题
   独立使用模式：跳过此步
```

**变更来源空白处理**（三项来源均不满足时）：
```
AskQuestion(
  prompt: "请提供本次回写的变更来源（至少一项）：",
  options: [
    { id: "describe", label: "我来描述改动内容" },
    { id: "file",     label: "提供代码文件路径" },
    { id: "git",      label: "使用 git diff 查看最近变更（需在 git 仓库中）" }
  ]
)
- 选"描述" → 等待用户输入后继续
- 选"文件" → 等待用户提供路径后 Read
- 选"git"  → Shell: git diff HEAD~1 --name-only，列出变更文件后 Read 相关文件
```

## 执行流程

```
Step 1：读取现有 PRD

  Read {PRD 文件路径}
  重点关注：§4.2 页面清单、§4.3 功能描述、§6.x 状态机、§9.x 异常边界

  PRD 格式检测：
    扫描文件是否含 "§4.2" / "页面清单" / "状态机" 等关键节标题
    若未找到标准节结构 → 调用 AskQuestion：
    AskQuestion(
      prompt: "您的 PRD 未使用标准 §4.x 节结构。回写时如何处理？",
      options: [
        { id: "freeform",    label: "保持原文件结构，在最相关段落末尾追加变更说明" },
        { id: "add_section", label: "在文件末尾新增「变更记录」节统一记录" },
        { id: "restructure", label: "按全流程 PRD 格式重新整理（可能改变文件结构）" }
      ]
    )

Step 2：分析代码变更

  代码框架检测（Read 代码文件后自动判断）：
    .vue / script setup / defineProps → Vue 3
    .tsx / .jsx / import React        → React
    @Component / NgModule             → Angular
    其他 → 通用模式（只分析逻辑，不依赖框架语法）
  框架不影响 PRD 回写（PRD 描述功能意图，非实现细节），各框架均可继续执行
  在回写摘要中注明检测到的框架类型

  将变更分类：
    A. 新增功能/状态/字段 → 需要在 PRD 中新增
    B. 修改了已有逻辑 → 需要在 PRD 中更新对应段落
    C. 删除/废弃了某功能 → 需要在 PRD 中标注废弃或删除

Step 3：变更确认（调用 AskQuestion）

  列出推断出的 PRD 变更点，请用户确认：
  AskQuestion(
    prompt: "根据代码变更，以下内容需要更新到 PRD，请确认：",
    allow_multiple: true,
    options: [每个变更点一个 option，含变更描述和影响的 PRD 章节]
  )
  - 用户勾选的变更点 → 执行回写
  - 用户未勾选的变更点 → 跳过，不修改 PRD

Step 4：执行回写

  对每个用户确认的变更点，使用 StrReplace 更新 PRD 对应段落：
  - 新增 → 在对应章节末尾追加
  - 修改 → 替换对应描述
  - 废弃 → 在对应条目添加 ~~删除线~~ 并追加"（已废弃，{日期}）"
  
  格式兼容（Step 1 中用户选择了非标准结构）：
  - freeform    → 找到最相关段落，在末尾追加"---\n**变更说明（{日期}）**：{内容}"
  - add_section → 在文件末尾追加"## 变更记录\n| {日期} | {变更描述} |"
  - restructure → 按标准 PRD §4.x 结构重新组织文件内容

Step 5：版本快照

  确认快照目录存在（若不存在则创建）：
  全流程模式：Shell mkdir -p docs/ux/{模块名}/versions/
  独立使用模式：按 Step 0 中用户选择的快照路径执行（skip → 跳过此步骤）

  快照命令：Shell cp {PRD路径} {快照目录}/s4-prd-writeback-{YYYYMMDD}.md

  在 PRD 文件头部或 ## 变更记录 节追加记录：
  | {日期} | 代码回写 | {变更摘要} |

Step 6：更新 session-state.md

  全流程模式：在「已完成」节追加：
    - Stage 4 → PRD 回写：{N} 处变更（版本快照：versions/s4-prd-writeback-{YYYYMMDD}.md）
  独立使用模式：跳过此步骤（无 session-state.md）
```

## 输出摘要（对话中呈现）

**增量回写模式**：
```
## PRD 回写完成

模式：{全流程 / 独立使用}
代码框架：{Vue 3 / React / Angular / 通用}
PRD 格式：{标准 §4.x / 自由格式（{用户选择的处理方式}）}

已更新 {N} 处：
- {变更点 1}：更新了 §{章节} / {段落描述}
- {变更点 2}：...

版本快照：{快照路径}（若执行）
活跃文件：{PRD 文件路径}（已更新）

跳过 {M} 处（用户未确认）
```

**从零生成模式**：
```
## PRD 从零生成完成

模式：从零生成（代码逆向）
扫描页面：{N} 个（{页面名列表}）
PRD 格式：{标准 §4.x / 轻量}

生成内容：
- 页面清单：{N} 个页面
- 数据模型：{N} 个字段
- API 接口：{N} 个
- 状态机：{N} 个状态（标准格式）
- 验收用例：{N} 条（标准格式）

⚠️ 由代码逆向推断，建议人工核对业务规则的准确性

版本快照：{路径}/versions/s0-prd-from-code-{YYYYMMDD}.md
新建文件：{PRD 文件路径}
```

## 质量门控（自检）

**通用（所有模式）**：
- [ ] 模式检测已执行（全流程 / 独立使用 / 从零生成）
- [ ] 版本快照已创建（或用户选择跳过）
- [ ] 输出摘要已呈现（含模式标注）

**增量回写模式额外检查**：
- [ ] 所有用户确认的变更点都已更新到 PRD
- [ ] PRD 格式兼容处理已按用户选择执行
- [ ] 变更记录已追加到 PRD 变更历史节
- [ ] 全流程模式：session-state.md 已更新
- [ ] 未修改用户未确认的内容
- [ ] PRD 整体结构保持完整，未破坏其他章节

**从零生成模式额外检查**：
- [ ] Step G0 扫描范围已由用户勾选确认
- [ ] Step G2 大纲已由用户确认后才生成正文
- [ ] PRD 文件头部含免责声明（"由代码逆向生成"警示）
- [ ] 快照命名使用 s0-prd-from-code 前缀（区别于回写快照）
- [ ] 生成内容基于代码事实，不虚构未在代码中体现的业务规则
