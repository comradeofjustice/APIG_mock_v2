# Design Validation（设计验证）

在设计稿进入前端代码前，用低成本过滤明显问题。定位是**代码级 Lint 的设计版**：不能替代真实用户测试，但能让真正重要的测试更聚焦。

---

## 执行前准备

```
1. get_editor_state()          确认当前 .pen 文件
2. get_screenshot(pageId)      获取目标画板截图
3. 读取 Stage 2 PRD 文件（docs/ux/{模块}/prd.md）作为评估基线
4. 读取项目设计规范（若存在 b-admin-pencil-design skill）
```

## 子工具及触发规则

| 子工具 | 默认状态 | 触发条件 | 输出文件 |
|---|---|---|---|
| 启发式评估 | **默认执行** | 有 Pencil 截图即可 | `heuristic-report.md` |

## 子工具一：启发式评估（Heuristic Evaluation）

### 评估框架

对照以下三层框架，逐项扫描截图和设计说明：

#### 层一：Nielsen 10 条启发式原则

| # | 原则 | 检查要点 |
|---|---|---|
| 1 | 系统状态可见性 | 加载/空态/错误态是否可见；操作后是否有反馈 |
| 2 | 系统与现实世界匹配 | 用词是否贴近用户语言；图标含义是否直觉 |
| 3 | 用户控制与自由度 | 危险操作是否可撤销；误操作是否有出口 |
| 4 | 一致性与标准 | 同类组件行为是否一致；操作区位置是否统一 |
| 5 | 错误预防 | 高风险操作是否有二次确认；表单是否有前置校验 |
| 6 | 识别优于回忆 | 筛选条件是否持久可见；当前状态是否始终展示 |
| 7 | 灵活性与效率 | 高频操作是否有快捷路径；批量操作是否支持 |
| 8 | 美观与简约 | 是否有冗余信息；视觉噪音是否过多 |
| 9 | 帮助识别/诊断/恢复错误 | 错误提示是否明确说原因和修复方式 |
| 10 | 帮助与文档 | 复杂操作是否有引导；空态是否有行动指引 |

#### 层二：设计系统合规检查（若项目有规范）

> 规则读取自 **单一数据源**：执行此步骤前，先用 Read 工具读取
> `~/.cursor/skills/b-admin-pencil-design/core/compliance-checklist.md`
> 获取最新规则，然后逐项对照检查。不在本文件维护规则副本。

#### 层三：WCAG 基础可访问性（最小集）

- [ ] 文字与背景对比度 ≥ 4.5:1（正文）/ 3:1（大字标题）
- [ ] 交互元素不只靠颜色区分状态（需配合文字或图标）
- [ ] 焦点状态可见（键盘导航可用）

```markdown
# 启发式评估报告 — {模块名}

**评估时间**：{日期}
**评估范围**：{画板名称列表}
**设计文件**：{.pen 文件路径}

---

## 问题清单

| # | 位置 | 问题描述 | 违反原则 | 修复建议 |
|---|---|---|---|---|

### P1 — 重要（建议在首次上线前修复）
| # | 位置 | 问题描述 | 违反原则 | 修复建议 |
|---|---|---|---|---|

### P2 — 优化（可排入后续迭代）
| # | 位置 | 问题描述 | 违反原则 | 修复建议 |
|---|---|---|---|---|

---

## 合规检查结果
（逐项标注通过 ✓ / 不通过 ✗ / 不适用 —）

- P1 问题数：X 个
- P2 问题数：X 个
- 总体评价：[可进入 Stage 4 / 需修复后重新评估]
```

### Gate 条件

> Gate 结果在「评估后修复确认流程」（见下节）执行完毕后，根据剩余未修复 P0 数量重新判定：
> - **P0 剩余 = 0** → Gate 通过，可进入 Stage 4
> - **P0 剩余 > 0** → Gate 继续阻断，告知用户剩余数量

## 评估后修复确认流程（⛔️ 写完 heuristic-report.md 后必须执行）

> 本节在「子工具一」写完报告后、宣布 Gate 结果前顺序执行。
> 三个步骤按 P0 → P1 → P2 顺序进行，各步骤之间互相独立，不得合并为单次 AskQuestion。

### Step A — P0 修复确认（仅 P0 > 0 时执行）

```
1. 从 heuristic-report.md 提取所有 P0 条目（编号 + 简要描述）
2. AskQuestion（allow_multiple: true）：
   prompt: "以下 P0 问题是进入 Stage 4 的阻断条件，必须全部修复后 Gate 才能通过。
            请勾选希望立即在 Pencil 中修复的项（建议全选；
            取消勾选的项将继续阻断 Stage 4）"
   options: [每个 P0 条目一个 option，含编号和位置描述]
3. 用户勾选 → 逐项执行 batch_design 修复 → heuristic-report.md 对应行标记 ✅ 已修复
4. 用户未勾选某项 → heuristic-report.md 标记 ⏸️ 用户暂缓
                 → 写入 session-state.md ## 已知问题 节
                 → Gate 继续阻断（该项未修复）
```

### Step B — P1 修复确认（仅 P1 > 0 时执行）

```
1. 从 heuristic-report.md 提取所有 P1 条目（编号 + 简要描述）
2. AskQuestion（allow_multiple: true）：
   prompt: "以下 P1 问题建议在首次上线前修复（不影响当前 Gate）。
            请勾选希望现在在 Pencil 中修复的项
            （取消勾选的将记录为延期，不阻断 Stage 4）"
   options: [每个 P1 条目一个 option]
3. 用户勾选 → 执行修复 → heuristic-report.md 标记 ✅ 已修复
4. 用户未勾选 → heuristic-report.md 标记 ⏭️ 延期
              → 写入 session-state.md ## 已知问题 节
```

### Step C — P2 修复确认（仅 P2 > 0 时执行）

```
1. 从 heuristic-report.md 提取所有 P2 条目（编号 + 简要描述）
2. AskQuestion（allow_multiple: true）：
   prompt: "以下 P2 优化项可排入后续迭代（不影响 Gate 和上线）。
            是否希望现在在 Pencil 中修复部分？
            （全部不选即跳过，写入延期记录）"
   options: [每个 P2 条目一个 option]
3. 用户勾选 → 执行修复 → heuristic-report.md 标记 ✅ 已修复
4. 用户未勾选 → heuristic-report.md 标记 ⏭️ 延期
              → 写入 session-state.md ## 已知问题 节
```

### Step A-C 完成后 — 重新判定 Gate

```
重新统计 heuristic-report.md 中 P0 剩余（非 ✅ 已修复）条数：
- P0 剩余 = 0 → Gate 通过，可进入 Stage 4
- P0 剩余 > 0 → Gate 继续阻断，对话中列出剩余 P0 条目，等待用户决策
```

## 子工具二：预测性热图分析（默认执行）

> **实现规范**：执行本步骤前，用 Read 工具读取 `~/.cursor/skills/pencil-heatmap/SKILL.md`，按其中步骤（`export_nodes` 导出 PNG、`dim-overlay` + `thermal-blobs` 层级、`G()` prompt 模板、负向提示词）生成热图画板。以下小节为**推断逻辑与报告模板**；Pencil 操作细节以 `pencil-heatmap` 为准。

基于视觉设计原则（尺寸、对比度、颜色、位置、留白）对截图做注意力分布推断，模拟眼动追踪效果，识别三类区域：

**红/橙区域（高关注度）**：视线首先落点、停留最久
- 判断依据：视觉对比最强、字号最大、位置居于视觉重心（F 型/Z 型扫描路径起点）

**黄/绿区域（中低关注度）**：用户会扫视但注意力较弱
- 判断依据：次级文本、辅助信息、中等对比度元素

**暗区（低关注度）**：用户大概率会忽略的背景或次要信息
- 判断依据：低对比度、边缘位置、大面积纯色背景

### 执行步骤

```
1. Read ~/.cursor/skills/pencil-heatmap/SKILL.md
2. 基于截图进行注意力分布推断，确定三类区域的界面坐标范围（用于 G() prompt 中的区域描述）
3. 按 pencil-heatmap：export_nodes → 新建热图画板 → dim-overlay + thermal-blobs 层级 → G() 生成热力层 → 可选底部图例文案
4. 若 AI 图未渲染完成：等待 10～15 秒后 get_screenshot 复核（见 pencil-heatmap「已知坑」）
5. 必须用 get_screenshot(heatFrameId) 截图确认热图画板已在 .pen 中生成，
   将截图节点 ID 记录到 heuristic-report.md 的「热图画板」字段。
6. ⛔ 严禁降级：不得以任何理由（资源限制、设计不完整、截图失败等）
   将本步骤替换为纯文字版。若 export_nodes 失败，向用户报告具体错误；
   若 G() 生成图片未渲染，等待后重试，而非跳过。
```

### 评估维度

对照热图推断结论，评估：
- 核心操作按钮是否落在高关注区
- 关键状态信息是否落在高/中关注区
- 重要警告/提示是否被暗区覆盖（若有，标记为 P1 问题）

### 输出

**主产出**：`.pen` 文件内新画板 `{模块名} - 热图分析`，可视化热力叠加效果

**辅助产出**（追加到 `heuristic-report.md`）：

```markdown
---
## 预测性热图分析

**热图画板**：{.pen 文件路径} → 画板「{模块名} - 热图分析」

### 注意力分布推断
| 区域类型 | 界面位置 | 内容元素 | 设计建议 |
|---|---|---|---|
| 红/橙（高关注） | ... | ... | ... |
| 黄/绿（中低关注） | ... | ... | ... |
| 暗区（低关注） | ... | ... | ... |

### 关键路径评估
- 主操作入口（如「新建」「发布」）：{在高关注区 ✓ / 在暗区 ✗}
- 状态标识（徽章/标签）：{可见度评级}
- 重要提示/警告：{是否在关注盲区}
```

**完成验证（必须执行）**：热图画板生成后，使用 AskQuestion 工具向用户确认，选项如下：
- "热图效果正常，继续" → 进入下一子工具
- "热图未显示 / 效果异常" → 重新执行步骤 3-4，向用户报告具体错误后再继续

## 子工具三：A/B 变体生成（按需）

### 触发条件

用户明确说存在设计决策分叉，例如：
- "不确定用卡片还是列表"
- "不知道筛选区放顶部还是侧边"
- "两个导航结构都在考虑"

### 执行步骤

```
1. 明确分叉点（当前方案 A 是什么，候选方案 B 是什么）
2. 在 Pencil 创建新画板（命名 "{模块名} - 方案B"）
3. 实现方案 B 的核心差异（不必全量，只需体现关键区别）
4. 撰写假设文档
```

### 假设文档格式（写入 `ab-hypothesis.md`）

```markdown
# A/B 变体假设文档 — {模块名}

## 决策背景
{描述为什么有这个分叉，当前各方的考量是什么}

## 方案 A（当前设计）
- 核心特征：
- 适用假设：{在什么用户行为假设下，A 更优}
- 预期指标：{任务完成率 / 操作步骤数 / 用户满意度}

## 方案 B（替代设计）
- 核心特征：
- 适用假设：{在什么用户行为假设下，B 更优}
- 预期指标：

## 验证方法
- [ ] 用户访谈（5 人，定性）
- [ ] 可用性测试（任务完成率对比）
- [ ] A/B 测试（需要流量，上线后）

## 推荐默认
若无法立即测试，推荐采用方案 {A/B}，原因：{简述}
```

## 质量门控（自检）

- [ ] 每个问题都有"位置 + 描述 + 违反原则 + 修复建议"四要素
- [ ] P0 问题的修复建议具体可操作（不是"优化体验"这类模糊表述）
